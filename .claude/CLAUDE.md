# CLAUDE 共通運用ルール（qbl）

## このリポジトリの前提
- このリポジトリは **Next.js + Supabase** で構成された本体アプリ（公開サイト + CMS 同居）である。
- 既存の `app/`, `components/`, `lib/`, `public/` は既存機能を支えるため、無関係な変更を入れない。

## 変更方針
- 既存実装を壊す大きな変更より、**小さく可逆な変更**を優先する。
- 変更前に影響範囲（import 参照、利用ページ、API、型）を確認する。
- 1 変更につき 1 目的を意識し、レビュー可能な粒度で進める。

## ディレクトリ責務
- 記事運用資料（調査メモ、ブリーフ、チェックリスト、プロンプト）は `content-ops/` 配下に置く。
- アプリコードと editorial 資産を混同しない（`app/` と `content-ops/` を分離する）。

## セキュリティ
- `service_role` はブラウザに出さない。`NEXT_PUBLIC_*` に載せない。
- 秘密情報は `.env.local` などの環境変数で管理し、コード直書きしない。

## 品質ゲート
- 可能な限り `lint` / `typecheck` 前提で作業を終える。
- 仕様変更を伴う場合は、最低限の確認手順を作業メモに残す。

## DB スキーマ管理
- DB schema の正本は **Supabase DB 本体 + migration** で管理する。
- スキーマ変更は `supabase/migrations/` に反映し、実 DB と乖離させない。
