# app-code ルール

## 対象
- `app/`, `components/`, `lib/` を変更する作業。

## 原則
- 破壊的リファクタは避ける。既存 import / 既存 route を壊さない。
- 既存 UI と導線を勝手に変更しない。必要な場合は変更理由を明記する。
- 1変更1目的でコミット可能な差分を作る。

## サーバー/クライアント境界
- `service_role`, 管理用トークン, 内部 API キーは server-only で扱う。
- クライアントに出してよい情報は公開前提の値のみ（`NEXT_PUBLIC_*` を含む）。
- データ取得は既存の責務分離（Server Component / API Route / Action）を維持する。

## 実装時チェック
- 既存の型・バリデーション・エラーハンドリング方針に合わせる。
- 既存ページの URL 構造や CMS 側の期待フォーマットを変えない。
- 変更後に最低限 `lint` / `typecheck` で壊れていないことを確認する。
