# security ルール

## 秘密情報の扱い
- `.env.local` の中身を出力しない。ログ貼り付け時もマスクする。
- API キー、トークン、秘密鍵をコードに埋め込まない。
- シークレットは環境変数 / Secret Manager で扱う。

## Supabase の原則
- `service_role` は Edge Functions または server-only でのみ使用する。
- `service_role` を `NEXT_PUBLIC_*` に入れない。クライアントに返さない。
- RLS 前提の設計を崩す変更は避け、必要時はレビュー前提で実施する。

## ログと監査
- 秘密情報、個人情報、認証情報をログに出さない。
- エラー共有時は再現に不要な機密値を削除してから共有する。

## 高リスク変更
- 本番系の認証・権限・ポリシー変更は慎重に扱う。
- 影響範囲、ロールバック手順、検証手順を明記してから適用する。
